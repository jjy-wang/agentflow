# RELEASE —— 发布与回滚

## 灰度策略

系统天然多实例（app1/app2），灰度按实例进行，无需额外基础设施：

1. **准备**：确认错误预算充足（见 `docs/SLO.md`，预算耗尽冻结发布）；确认数据库迁移已按 expand-only 先行并验证旧版可用。
2. **灰度第一台**：升级 app1，观察 15 分钟。硬性观察项：
   - `agent.run.total{state=failed}` 速率不高于基线；
   - `agent.ttft` P95 ≤ 1500ms；
   - `llm.error.total` 无突增；
   - 优雅停机期间 app2 接管 run 无丢失（恢复任务日志可见抢占记录）。
3. **全量**：app1 健康则升级 app2；任何一项不达标立即回滚 app1 并中止。
4. **验证**：灰度期用独立 API Key 发起一条含工具调用的 run（`X-Mock-Tool: asset_search`），确认 `run.succeeded` 与审计链落库正常。

流量切换依赖前置负载均衡（生产环境 LB 按实例权重）；本地演示用端口直连（8080/8081）观察两实例行为。

## 回滚步骤

1. **应用回滚**：因迁移遵循 expand-only（见 `docs/MIGRATION.md`），旧版本镜像可直接替换新版本重新部署，数据库无需回退；
2. **生效确认**：回滚实例启动后，确认其重新加入租约竞争（`RunRecoveryJob` 日志出现抢占记录）、SSE 连接恢复增长；
3. **在途 run 处理**：发版/回滚中被中断的 run 由租约过期 + 恢复任务自动接管（最长 60s + 5s 扫描周期），无需人工干预；人工介入仅用于 `state_json` 损坏的个案（置 `FAILED` 并通知调用方）；
4. **指标复核**：回滚后 15 分钟内对照发版前基线复核 6 条告警全部静默；
5. **复盘**：回滚原因进复盘，若涉及结构变更，检查是否违反 expand-only 规范。

## 停机流程

优雅停机是发版与回滚的公共路径，目标是"没有连接被硬断、没有任务被丢失"：

1. **摘除流量**：LB 摘除目标实例（本地演示直接 `docker compose stop app1`）；
2. **停止接收新请求**：`server.shutdown=graceful` 生效，Netty 拒绝新连接，存量请求继续；
3. **存量收敛**（最长 30s，`timeout-per-shutdown-phase`）：
   - SSE 流：运行中的 run 继续推流直至终态事件；客户端断开即级联取消；
   - 未完成的 run：实例停止续期租约，60 秒内由存活实例 `SKIP LOCKED` 抢占续跑；
4. **资源回收**：关闭阶段依次释放模型连接（WebClient）、舱壁信号量、PG/Redis 连接池；
5. **验证**：`docker logs` 无 `InterruptedException` 之外的异常关闭记录；PG 中无 `lease_owner` 指向已停实例且未过期的 run 超过 120 秒（对应告警 5）。

**禁止**：`kill -9` 直接打实例（绕过优雅停机，run 要等租约过期才被接管，恢复延迟拉长到 60s+）；在错误预算耗尽窗口安排发版。

## 发布检查单

每次发布前逐项打勾，任一项不满足则暂停：

- [ ] `mvn verify` 通过（含 ArchUnit 与 JaCoCo 60% 门槛），CI 绿灯；
- [ ] 数据库迁移遵循 expand-only，已在预发库执行并用旧版应用验证可用；
- [ ] 6 条告警当前全部静默，错误预算充足；
- [ ] 变更不涉及 `loadtest` 禁止事项（不引入真实模型调用）；
- [ ] 回滚镜像版本号已确认可拉取，回滚步骤已评审；
- [ ] 灰度观察人、观察指标、中止条件已明确并通知值班。

## 版本兼容矩阵

| 组件 | 兼容要求 |
|---|---|
| 应用 ↔ 数据库 | 应用旧版必须能跑在新版结构上（expand-only 保证）；反向不保证 |
| 应用 ↔ SSE 客户端 | 事件类型只增不改义；新增事件类型旧客户端应忽略未知 `event:` |
| 应用 ↔ mock/供应商 | 仅依赖 OpenAI 兼容流式协议；协议变更走 ADR 0002 的跟进流程 |
| 应用 ↔ Redis Lua | `quota_reserve.lua` / `quota_settle.lua` 与应用同版本发布，禁止单独热改 |
