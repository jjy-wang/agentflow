# SLO —— 服务水平目标

## SLI 定义

| SLI | 指标来源 | 计算方式 |
|---|---|---|
| 可用性 | `agent.run.total{state}` | 成功 run 数 / 总 run 数（`state=succeeded` 占比；客户端主动取消 `canceled` 不计入失败） |
| TTFT 延迟 | `agent.ttft`（Prometheus 直方图） | 5 分钟窗口 `histogram_quantile(0.95, rate(agent_ttft_bucket[5m]))` |
| 端到端延迟 | `agent.run.duration` | 5 分钟窗口 P95 |
| 限流正确性 | `quota.rejected.total` + 预扣结算对账 | 无超发（供应商侧 429 为 0）；结算后桶余量回正 |
| 流式完整性 | `backpressure.drop.total`、状态事件丢失数 | 状态迁移类事件（`run.*`/`tool.*`）零丢失；`llm.delta` 丢帧率可观测 |

## SLO 目标

| SLI | 目标 | 窗口 |
|---|---|---|
| 可用性 | ≥ 99.5% | 28 天滚动 |
| TTFT P95 | ≤ 1500 ms | 5 分钟 |
| 端到端 P95 | ≤ 8000 ms（多轮 ReAct 场景） | 5 分钟 |
| 限流正确性 | 供应商侧 429 = 0；结算漏损率 < 0.01% | 每日对账 |
| 流式完整性 | 状态事件丢失 = 0；慢客户端踢除有指标、有告警 | 持续 |

压测入口阈值（CI 门槛）：`baseline.js` 的 `ttft_ms` P95 < 1500ms、`http_req_failed` < 1%；`agent_multi_turn.js` 的 `run_e2e_ms` P95 < 8000ms。

## 错误预算

以 28 天可用性 99.5% 计：

- 月预算 = 0.5% 的 run 允许失败。假设月 100 万 run，预算 = 5000 次失败；
- 预算消耗速率告警：
  - 快速燃烧：1 小时消耗 > 2% 月预算 → 触发告警 1/3（TTFT / 模型错误）对应 Runbook；
  - 慢速燃烧：3 天消耗 > 50% 月预算 → 例会评审，冻结非必要变更；
- 预算耗尽：冻结一切非修复性发布（见 `docs/RELEASE.md` 灰度策略），直至回到预算内。

## 消耗策略

| 场景 | 是否消耗预算 | 说明 |
|---|---|---|
| 模型上游故障导致 run 失败 | 消耗 | 上游是我们的依赖，纳入自身 SLO；驱动舱壁/路由改进 |
| 配额拒绝（429） | 不消耗可用性预算 | 属于契约内限流，但计入"限流正确性"监控，异常突增走告警 2 |
| 客户端主动取消 | 不消耗 | `state=canceled` 从失败率分子分母同时剔除 |
| 发版窗口失败 | 消耗 | 不豁免，倒逼优雅停机与灰度质量 |
| 压测流量 | 不消耗 | 压测打 mock-llm，且压测 API Key 单独标记，指标可按 model 标签区分剔除 |
